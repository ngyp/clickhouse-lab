# 성능 기대 기준

[기대 기준](./README.md) · [데이터 결과 기준](./data-result.md)

데이터 정확성 검증을 통과한 케이스만 성능을 비교합니다. 아직 운영 목표값과 대용량 합성 데이터가 확정되지 않았으므로, 이 문서는 측정 항목을 먼저 고정합니다.

## 동일하게 유지할 조건

| 조건 | 기록할 값 |
|---|---|
| 데이터량 | 원본 행 수, 고유 journey 수, 중복률, 보존 기간 |
| 클러스터 자원 | shard·replica 수, Pod CPU·메모리, 디스크 |
| 조회 조건 | 상품 수, 조회 기간, 이벤트 종류, 고객 그룹 수 |
| 동시성 | 적재 동시성, 조회 동시성 |
| 실행 상태 | cold/warm cache, 적재·merge 동시 수행 여부 |
| 반복 횟수 | 워밍업 횟수와 실제 측정 횟수 |

## 측정 항목

| 구분 | 지표 | 합격 목표 |
|---|---|---|
| 적재 | 초당 처리 행 수, batch 크기, 실패율 | 미정 |
| 누적 조회 | 응답 시간 p50·p95·p99 | 미정 |
| 시간별 조회 | 응답 시간 p50·p95·p99 | 미정 |
| 고객 그룹 조회 | 응답 시간 p50·p95·p99 | 미정 |
| 자원 | CPU·메모리 최대값, 읽은 행·바이트 | 미정 |
| 저장소 | 압축 후 크기, 디스크 처리량, merge backlog | 미정 |
| 반영 지연 | event 입력부터 RDS·summary 조회 반영까지 | 미정 |

A1~A7은 같은 입력과 조회 범위를 사용하되, 각 케이스의 정상 조회 경로로 측정합니다. A7은 최소 `occurred_at` 정책 차이를 결과 비교에서 분리합니다. 평균만 비교하지 않고 p95·p99와 최대 메모리도 함께 기록합니다.

운영 요구사항이 확정되면 `미정` 값을 실제 목표로 바꾼 뒤 테스트합니다. 결과를 보고 목표값을 사후에 완화하지 않습니다.
