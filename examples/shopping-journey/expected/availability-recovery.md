# 가용성·복구 기대 기준

[기대 기준](./README.md) · [데이터 결과 기준](./data-result.md)

장애 중 서비스 지속 여부와 장애 해소 후 데이터 복구를 평가합니다. 현재는 시나리오와 관측 항목을 정의하며, 허용 중단 시간과 성공률은 운영 요구사항을 반영해 확정해야 합니다.

## 목표

| 항목 | 목표 |
|---|---|
| 읽기 연속성 | 단일 ClickHouse Pod 장애 중에도 조회 경로 유지 |
| 쓰기 연속성 | 재시도·우회 경로를 포함해 최종 적재 성공 |
| 데이터 보존 | 복구 완료 후 누락·이중 집계 없이 데이터 결과 기준과 일치 |
| ClickHouse 복구 시간 | 미정 |
| Keeper 복구 시간 | 미정 |
| 허용 요청 실패율 | 미정 |

## 장애 시나리오

| 시나리오 | 확인할 내용 |
|---|---|
| ClickHouse Pod 1개 종료 | 같은 shard의 replica로 읽기·쓰기 우회 여부 |
| ClickHouse 노드 1개 중단 | 해당 노드의 여러 Pod 영향과 분산 조회 성공 여부 |
| replica 재기동 | replication queue 해소와 데이터 수렴 시간 |
| Keeper 1개 종료 | 2/3 quorum 유지와 복제 작업 지속 여부 |
| Keeper 복구 | 세션·리더·복제 상태 정상화 시간 |
| 적재 중 장애 | 재시도 후 누락·중복 없는 최종 결과 |

## 공통 판정 방법

1. 장애 직전 기준 행 수와 집계 결과를 기록합니다.
2. 일정한 적재·조회 부하를 유지하며 장애를 발생시킵니다.
3. 장애 중 요청 성공률과 오류 종류를 기록합니다.
4. Pod와 replica 상태가 정상화될 때까지 시간을 측정합니다.
5. 복구 후 [데이터 결과 기준](./data-result.md)을 다시 실행합니다.

모든 Pod의 로컬 행 수를 더해 데이터 보존 여부를 판단하지 않습니다. 애플리케이션 조회 경로의 논리 결과와 replica 동기화 상태를 함께 확인합니다.
